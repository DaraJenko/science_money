Gitとは

ファイルの変更履歴を記録・参照するための分散型バージョン管理ソフトです。
分散型とは、サーバーだけでなくローカルのPCに履歴をコピーして、
記録の編集や参照ができる形式を指します。
なお、記録のことをcommit(コミット)と呼んだりします。

Gitの利点

具体的に何が便利なのか、例を挙げます。

1. 気軽に「元に戻せる」安心感

例えば、あるプログラムファイルがあり、新機能の開発をするとします。
開発が中止となっても、commitしておいた地点まで戻せます。

2. 変更理由を後から追える

commitにはメッセージを添えられるため、変更理由をあとで見返すことができます。
不具合が起きたときに、原因の特定をしやすくなります。

3. 並行作業が簡単

branch(ブランチ)というgitコマンドを使うと、履歴を分岐させることができます。
例えば、現行のプログラムは稼働しつつ、新機能を開発したいとき、
複数の作業を同時進行させ、開発完了後に本流に取り込むことが可能です。

4. チームでの共同開発が可能

GitHubなどと組み合わせることで、同じプロジェクトに複数人が同時に手を加え、
変更内容をレビューしてから取り込む、といったチーム開発が可能です。
なお、このレビュー依頼をPull Request[PR](プルリクエスト)と言います。

GitとGitHubの違い

Git初心者がまず混同しやすいのが、GitとGitHubの違いです。

名前 内容
Git PCにインストールして使う、バージョン管理のソフトウェア。
GitHub Gitの全履歴(リポジトリ)をオンラインで共有できるサービス。
POINT Gitだけでもバージョン管理は可能です。
GitHubは「複数人での共同作業」や「クラウドへのバックアップ」を目的とした外部サービスです。
GitLabやBitbucketといった類似サービスもあります。

このシリーズで学ぶこと

このチュートリアルは、次のような流れで進みます。

  1. ①（本記事）Gitとは何か、何の役に立つのか
  2. ②　Gitの環境構築
  3. ③　リポジトリを作って基本コマンドを実践する
  4. ④　ブランチとマージを実践する
  5. ⑤　リモートリポジトリの操作とリベースの基礎

実際に手を動かしながら進める構成にしているので、
②以降は実際にターミナル（コマンドライン）を開いて、
一つずつコマンドを打ってみることをおすすめします。

NOTE ブランチ操作をブラウザ上のアニメーションで視覚的に学べる Learn Git Branching という有名な学習サイトもあります。
本シリーズで文章として理解した後、そちらでコミットの流れを確認しながら手を動かすと、
理解が定着しやすいと思います。

まとめ

Gitは「変更履歴を記録し、必要なときに参照・復元できるようにする」ためのツールであり、
GitHubはそのGitのリポジトリをネット上で共有・共同編集するためのサービスです。
次回は、実際に自分のPCにGitをインストールし、使える状態にします。
